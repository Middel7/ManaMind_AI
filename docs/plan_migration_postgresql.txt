commandant, TF-IDF, etc.) sont stockées sous forme de CSV dans data/stats/.
Les decklists sources se trouvent sur le Bureau à :

  → Plusieurs centaines de milliers à millions de lignes au total

Le projet possède déjà Alembic configuré et des tables existantes (cards,
import_runs, printings…). PostgreSQL est aussi utilisé dans un microservice
séparé. L'objectif est d'intégrer les données de stats dans la même base
PostgreSQL de ManaMind AI, sans créer de second système.

DÉCISION D'ARCHITECTURE
-----------------------
- PostgreSQL (pas SQLite) : indispensable en production avec Uvicorn multi-worker
- Tout dans ce repo : la base de stats n'est pas un service partagé
- Alembic pour le schéma : migrations versionnées, cohérent avec l'existant
- Les CSV sources (Bureau) restent en place : ils servent de source de vérité
  pour régénérer la base à tout moment (re-import ou mise à jour)
- Les fichiers data/My decks/*.txt restent tels quels : ce sont les decklists
  personnelles modifiables, pas des données de stats

PHASE 1 — SCHÉMA DE BASE DE DONNÉES
================================================================================

Nouvelle migration Alembic à créer : 20260703_add_deck_stats.py

Tables à créer :

  1. commanders
     - id          SERIAL PRIMARY KEY
     - name        TEXT NOT NULL UNIQUE        (nom canonique, ex: "Aesi, Tyrant of Gyre Strait")
     - name_norm   TEXT NOT NULL UNIQUE        (normalisé pour lookup rapide)
     - deck_count  INT NOT NULL DEFAULT 0      (nombre total de decks dans la base)
     - unique_cards INT NOT NULL DEFAULT 0
     - created_at  TIMESTAMPTZ DEFAULT now()
     - updated_at  TIMESTAMPTZ DEFAULT now()

  2. decks
     - id            SERIAL PRIMARY KEY
     - external_id   TEXT NOT NULL UNIQUE      (nom du fichier CSV sans extension)
     - commander_id  INT NOT NULL → FK commanders(id)
     - deck_type     TEXT                      (colonne "Deck Type" du CSV)
     - bracket       TEXT                      (colonne "Bracket" du CSV)
     - created_at_source  TIMESTAMPTZ          (colonne "Date Created" du CSV)
     - imported_at   TIMESTAMPTZ DEFAULT now()

  3. deck_cards
     - deck_id   INT NOT NULL → FK decks(id)
     - card_norm TEXT NOT NULL                 (nom normalisé de la carte)
     - card_name TEXT NOT NULL                 (nom original)
     - quantity  INT NOT NULL DEFAULT 1
     - is_commander BOOLEAN DEFAULT FALSE
     - PRIMARY KEY (deck_id, card_norm)

  4. commander_frequency   ← remplace commander_frequency.csv
     - commander_id      INT NOT NULL → FK commanders(id)
     - card_norm         TEXT NOT NULL
     - card_name         TEXT NOT NULL
     - decks_with_card   INT NOT NULL
     - total_decks       INT NOT NULL
     - inclusion_rate    FLOAT NOT NULL
     - PRIMARY KEY (commander_id, card_norm)

  5. commander_tfidf       ← remplace commander_tfidf.csv
     - commander_id  INT → FK commanders(id)
     - card_norm     TEXT NOT NULL
     - card_name     TEXT NOT NULL
     - inclusion_rate FLOAT
     - idf           FLOAT
     - tfidf         FLOAT
     - tfidf_norm    FLOAT
     - PRIMARY KEY (commander_id, card_norm)

  6. global_frequency      ← remplace global_frequency.csv
     - card_norm        TEXT PRIMARY KEY
     - card_name        TEXT NOT NULL
     - decks_count      INT
     - global_frequency FLOAT
     - commanders_count INT
     - idf              FLOAT

Index à créer :
  - commanders(name_norm)                         ← lookup par nom normalisé
  - commander_frequency(commander_id)             ← toutes les cartes d'un commandant
  - commander_frequency(card_norm)                ← tous les commandants d'une carte
  - commander_tfidf(commander_id)
  - deck_cards(commander_id via deck) + card_norm ← requêtes croisées

PHASE 2 — SCRIPT D'IMPORT
================================================================================

Fichier : scripts/import_decklists_to_postgres.py

Ce script :
  1. Lit les dossiers de C:\Users\fabie\Desktop\decklists_csv\output_csv\
  2. Pour chaque dossier (= commandant) :
     a. Insère ou met à jour la ligne dans `commanders`
     b. Pour chaque CSV de deck dans le dossier :
        - Parse les lignes (délimiteur ";")
        - Insère le deck dans `decks` (external_id = nom du fichier)
        - Insère les cartes dans `deck_cards`
  3. Après l'import brut, calcule et insère dans `commander_frequency` :
     - decks_with_card = COUNT(deck_id) WHERE card_norm = X AND commander_id = Y
     - total_decks = deck_count du commandant
     - inclusion_rate = decks_with_card / total_decks * 100
  4. Calcule et insère dans `global_frequency` (agrégation toutes cartes)
  5. Calcule TF-IDF et insère dans `commander_tfidf`
  6. Journalise dans `import_runs` (table existante) : nb de decks, nb de cartes,
     durée, erreurs

Options CLI :
  --commander "Aesi, Tyrant of Gyre Strait"   (import d'un seul commandant)
  --recompute-stats-only                       (recalcule fréquences sans re-importer)
  --source-dir PATH                            (chemin alternatif au Bureau)

Performance attendue :
  - ~1 727 commandants × ~moyenne 300 decks × ~100 cartes = ~50 M lignes deck_cards
  - Import par batch (INSERT ... VALUES (...),(...) par lots de 1 000 lignes)
  - Durée estimée : 30-60 min en local sur le volume total
  - Les tables commander_frequency et commander_tfidf sont beaucoup plus petites
    (~200 commandants × ~150 cartes uniques = ~30 000 lignes chacune)
